## 2. Open decisions

### Needs your call before code

**D1 — Course identity (referenced by order seats in slice 2).**

| Option | Trade-off |
|---|---|
| A. UUID primary key generated by the database; `subject` is unique and is the seed's upsert key | Conventional surrogate key and nothing extra to maintain. The id differs per database, and the checkout URL carries a UUID. |
| B. Slug as primary key (`maths`, `english`, `science`) | Readable URLs and foreign keys, stable across resets. A natural key as PK is harder to defend if a subject is renamed or split per year (ADR 002 "In production"). |
| C. UUID primary key plus a unique `slug` exposed in URLs | Readable URLs with a surrogate key. Two identifiers to explain, and slice 2 must look up by slug. |

Recommendation: A.

**D2 — Price representation.**

| Option | Trade-off |
|---|---|
| A. Integer pence: column `pricePence Int`, contract `pricePence: number`, SPA formats with `Intl.NumberFormat('en-GB', …)` | No rounding issues, plain JSON number. The field name carries the unit; currency is implicitly GBP. |
| B. `Decimal(10,2)` | Reads like money in SQL. Prisma returns a `Decimal` object that serialises as a string, so the contract becomes `string` or needs a mapper. |
| C. Integer pounds | Simplest, but cannot express £199.50. |

Recommendation: A.

**D3 — Slice 1 / slice 2 boundary and how the selection travels.**
Slice 1 ends with a "Continue to checkout" primary button on the product page.

| Option | Trade-off |
|---|---|
| A. Query string: `/checkout?courseId=<id>&year=<n>` | Survives reload and direct open; slice 2 reads it and the API re-validates. Values are user-editable, which is fine because the server validates. |
| B. Router `state` on navigation | Clean URL, but lost on reload or direct open; checkout then needs a redirect-back branch. |
| C. Path params `/checkout/:courseId/:year` | Same properties as A with a stricter route; less natural for optional or additional fields later. |
| D. Client store or `sessionStorage` | Extra state layer for two values. |

Recommendation: A, with slice 1 registering `/checkout` as a placeholder page (`PageShell` plain, a heading and a "Back" link) so the button never leads to a dead route.

**Recording.** One ADR 017 "Catalogue contract: course identity, price in pence, selection in the URL" plus a line in `PROJECT.md`.

## 4. Brief for `tdd-guide`

Tests come first for the catalogue endpoint, the seed's idempotency and the product page's selection logic. Everything in `web/src/ui/`, `index.css`, `CheckoutPage.tsx` and the layout of `ProductPage` is presentational and untested.

**API integration — `api/src/catalogue/catalogue.int.spec.ts` (Jest + Testcontainers, real PostgreSQL).**
`tdd-guide` also creates the harness files (`jest.int.config.js`, `src/testing/*`) since they are test infrastructure. Arrange: `createTestApp()`, then `seedCourses(prisma)`.

1. `GET /api/courses` returns 200 and exactly three items: English 5–13, Maths 5–13, Science 5–11, each with `pricePence` 19900, in the agreed order (M3).
2. Each item has exactly the keys `id`, `subject`, `yearFrom`, `yearTo`, `pricePence`; `id` is a UUID string (D1).
3. Running `seedCourses` a second time leaves three rows and the same ids.

Expected RED: the suite fails on the missing `../seed` export and, once that exists, on a 404 for `/api/courses`. A container or migration error is not an acceptable RED; the harness must reach the application first.

**API unit — none new.** The service is a pass-through over Prisma, so a mocked-Prisma test would only restate the integration test. The existing `health.controller.spec.ts` must stay green with Docker stopped.

**SPA behaviour — `web/src/pages/ProductPage.test.tsx` (Vitest + RTL, `fetch` stubbed, `MemoryRouter`).**

1. Renders the three courses with subject, year range ("Years 5–13", "Years 5–11") and "£199".
2. Before a course is selected, the year select and "Continue to checkout" are disabled.
3. Selecting Science offers exactly years 5–11; selecting Maths offers exactly 5–13.
4. With Maths and Year 12 chosen, switching to Science clears the year and disables Continue.
5. With a course and a year chosen, Continue navigates to `/checkout?courseId=<id>&year=<n>` (assert through a probe route that prints the location).
6. When the request fails, an error `Notice` (`role="alert"`) is shown and no course controls are rendered.

Query by role and accessible name (radio group for courses, combobox for the year, button for Continue), so the tests do not depend on styling.

## 6. Risks and fallbacks

Claims are marked [V] verified on 2026-10-02 or [M] from memory.

### R1 — Testcontainers with Jest and Prisma 7

- **Packages.** `testcontainers` and `@testcontainers/postgresql` 12.2.0, pinned exact. [V] Both are CommonJS (`main: build/index.js`, no `type` field), so they load under ts-jest without ESM flags. [V] Engine range is Node >= 22.22; the host has 22.23.2. They are dev dependencies and only tests import them.
- **One container per run.** Jest `globalSetup` starts `PostgreSqlContainer('postgres:17-alpine')`, keeps the handle on `globalThis`, and `globalTeardown` stops it. [V]
- **Migrations.** `globalSetup` runs `npx prisma migrate deploy` with `cwd: api/` and the container URL in `DATABASE_URL`, the same command the `migrate` service uses. [V] `prisma.config.ts` picks the URL up from the environment.
- **`DATABASE_URL` into `PrismaService`.** `globalSetup` sets `process.env.DATABASE_URL`; test processes inherit it, so `PrismaService` needs no change. [V]
- **Spike result.** [V] Two spec files booting the real `AppModule`, `GET /api/health` through supertest and a query on `_prisma_migrations`: both passed, container start 1.5 s, migrate 2.1 s, about 6 s wall time in total, clean exit, no container left behind. The spike ran with ts-jest diagnostics off, so type-checking of the harness files is not yet proven.
- **Isolation.** One shared database, files run in band (M6). The catalogue is read-only and the seed is an upsert, so slice 1 needs no cleanup.
- **Unit tests without Docker.** The default Jest config ignores `*.int.spec.ts`; integration has its own config and script (M4).
- **Ryuk.** [V] Testcontainers pulls `testcontainers/ryuk:0.14.0`, which is not cached locally. The first spike run failed on that pull with a Docker Hub `EOF`; the registry answered seconds later, so it looked transient. The spike ran with `TESTCONTAINERS_RYUK_DISABLED=true`.

Fallbacks: pre-pull the Ryuk image, or set `TESTCONTAINERS_RYUK_DISABLED=true` in the `test:int` script (teardown already stops the container; a killed run would leave one behind). If ts-jest rejects the harness types, move the harness to plain `.js`.

### R2 — Seed in the runtime image

- `api/src/seed.ts` is compiled by `nest build` to `dist/seed.js`, so the image needs no TypeScript runner. It reuses `PrismaService` as a plain class and disconnects at the end. [M] `nest build` emits every file under `src`, not only those reachable from `main.ts`; step 5 checks it.
- Idempotency: `upsert` on the unique `subject`, updating range and price, so a changed seed value also corrects existing rows. Covered by integration test 3 and by the compose re-run.
- The `migrate` command needs a shell for `&&`. [M] `sh` exists in `node:22-slim`.
- [V] Prisma 7.10 config also has a `migrations.seed` command for `prisma db seed`; not needed here.

Fallback: if `dist/seed.js` is missing, add the file to the build explicitly, or run the seed as a second one-shot command in compose.

### R3 — Design foundation

- **Tokens.** [V] Tailwind 4.3.3 theme variables use the `--color-*`, `--font-*`, `--text-*` and `--text-*--line-height` namespaces. Colours go in as `--color-brand` and so on; type styles as `--text-display` with its line-height. [M] `--text-*--letter-spacing` and `--text-*--font-weight` companions exist as well; if not, tracking and weight are set by classes inside the primitives.
- **Notch.** [M] `@utility notch-sm` and `notch-lg` with an eight-point `clip-path: polygon(...)` cutting a square from the top-right and bottom-left (8px and 16px).
- **Notch side effects.** `clip-path` clips anything outside the box, including outlines and the corners of borders. The focus ring on notched buttons must therefore be inset (negative `outline-offset`), and a selected card is shown by background and an inset marker, not an outer border. This deviates slightly from "2px outline" in `DESIGN_SYSTEM.md`; worth a line in the doc.
- **Font.** [V] `@fontsource-variable/inter` 5.3.0 ships CSS plus `files/*.woff2`. [M] Importing it from `main.tsx` makes Vite emit the files to `dist/assets`, and the family name is `Inter Variable`. Tests import pages, not `main.tsx`, so jsdom never sees the CSS.
- **Native select.** Needs `appearance-none` and an explicit zero radius to stay square across browsers. [M]

Fallbacks: if font bundling misbehaves, use a system sans stack and note it in the design doc. If `@utility` fails, write the two classes as plain CSS in `index.css`.
